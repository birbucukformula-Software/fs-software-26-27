# 🐙 Görev 4: GitHub Operasyon ve Yönetim Kılavuzu

## 🎯 Amaç

Takım halinde yazılım geliştirirken kod yazmak kadar, kodu düzenli bir şekilde paylaşmak ve yönetmek de önemlidir. GitHub bunun için kullandığımız ana araçtır.

Bu görevde kod yazmanız beklenmiyor. Takıma yeni katılan bir üyeye GitHub'ı sıfırdan anlatacağınız bir eğitim sunumu hazırlayacaksınız.

## 🛠️ İstenen İçerik: Sunum Akışı

Sunumunuzda aşağıdaki dört ana başlığı işlemeniz beklenmektedir.

### Bölüm 1: Organizasyon Yönetimi

- **Organizasyon kurulumu:** GitHub'da organizasyon nasıl kurulur?
- **Takım (Team) yapısı:** Takım oluşturmak ne işe yarar? Örneğin yazılım ve elektronik ekipleri için yetkiler nasıl ayrılır?
- **Üye yönetimi:** Bir üyeyi organizasyondan çıkarmak ile takımdan çıkarmak arasındaki fark nedir?

### Bölüm 2: Temel Kavramlar

- **Repository:** Nedir? Public ve Private arasındaki fark nedir?
- **Fork vs. Clone:** Hangisi ne zaman kullanılır? Kalabalık takımlarda neden Fork tercih edilir?
- **Branch:** Neden ana dalda doğrudan çalışılmaz? Yeni dal nasıl açılır?
- **Commit:** İyi bir commit mesajı nasıl yazılır?

### Bölüm 3: Operasyonel Döngü

Şema ve ekran görüntüleriyle aşağıdaki adımları anlatın:

- Fork → Clone → Çalışma → Push → Pull Request
- Takım liderinin PR'ı nasıl incelediği
- Ana repo değiştiğinde Fork'u ve yerel kopyayı güncel tutma

### Bölüm 4: Kriz Yönetimi

- **Conflict (çakışma):** İki kişi aynı satırı değiştirirse ne olur? Çakışma adım adım nasıl çözülür?

# 🐙 Task 4: GitHub Operations & Management Guide

## 🎯 Objective

When developing software as a team, writing code is only part of the job; sharing and managing that code in an organized way matters just as much. GitHub is the main tool we use for this.

You are not expected to write any code in this task. Instead, you will prepare a training presentation that explains GitHub from scratch to a new team member.

## 🛠️ Required Content: Presentation Outline

Your presentation is expected to cover the following four main sections.

### Section 1: Organization Management

- **Organization setup:** How do you create an organization on GitHub?
- **Team structure:** What is the purpose of creating teams? For example, how are permissions separated between the software and electronics teams?
- **Member management:** What is the difference between removing a member from the organization and removing them from a team?

### Section 2: Core Concepts

- **Repository:** What is it? What is the difference between Public and Private?
- **Fork vs. Clone:** When is each one used? Why is Fork preferred in large teams?
- **Branch:** Why do we not work directly on the main branch? How do you create a new branch?
- **Commit:** How do you write a good commit message?

### Section 3: The Operational Cycle

Explain the following steps with diagrams and screenshots:

- Fork → Clone → Work → Push → Pull Request
- How the team lead reviews a PR
- Keeping your Fork and local copy up to date when the main repository changes

### Section 4: Crisis Management

- **Conflict:** What happens when two people modify the same line? How do you resolve a conflict step by step?

## 💡 Tips & Additional Contributions

- Drawing your own Git flow diagrams with tools like draw.io will earn extra credit during evaluation.
- The sections above provide a framework for your presentation; you are not required to limit yourself to them. You may include topics you find important during your research, takeaways from your own experiences, and any additional methods or examples you would like to share. You are expected to add your own contribution and perspective to the presentation.
